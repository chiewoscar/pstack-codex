### Shipping

Ship only the run the user authorized and independently verified. Read the Codex runtime mapping before delegating. GitHub CLI (`gh`) is the default; use the repository's configured forge integration when required. Graphite is optional, never a prerequisite.

1. **Resolve the repository, trunk and merge authorization.** Read the PRs and their base/head branches. A request to check or babysit does not authorize merging. Preserve the user's scope and repository merge policy.
2. **Verify each PR independently.** When authorized delegation is available, use a verifier that did not write the patch, its own checkout, the matching project verification skill, and parent-versus-head behavior. Return `PASS`, `PASS+NOTES`, or `FAIL`, with the head SHA, commands and evidence. Green CI alone is not behavioral proof. If independent verification is unavailable, disclose the gap and do not represent self-verification as independent. Post a verdict externally only when that write is authorized.
3. **Select the contiguous verified run from the bottom.** Stop at the first PR without a passing verdict and name that ceiling. A verified PR above the gap waits. Moving it to trunk requires a new verdict against its new base.
4. **Confirm the verdict still covers the patch.** Compare `git patch-id` for the reviewed patch with the current patch. Reverify changed behavior or dependency context. Require passing required checks for the current head. Do not reuse a verdict because only the SHA or CI looks familiar.
5. **Land bottom-up, one PR at a time.** Read the lowest PR's base immediately before merging. On GitHub it must target the verified trunk, not an unprotected parent branch. Use the repository-approved merge method, such as `gh pr merge <pr> --squash`. Never arm auto-merge on an upstack PR targeting its parent. Read `gh pr view <pr> --json state,mergedAt,baseRefName` afterward; queued or armed is not merged.
6. **Prepare the next PR only after its parent is confirmed merged.** Retarget its base to trunk, move its patch onto the merge result, and rerun required checks and patch verification. A rewritten branch may be pushed only within existing authorization; use `--force-with-lease` pinned to the last observed remote SHA. If another actor moved it, stop rather than overwriting their work. When Graphite manages the stack, use its established flow instead of mixing manual topology changes into its queue.
7. **Watch until the ceiling is actually merged.** Use bounded status checks in the active chat. On GitHub use `scripts/watch-pr/watch-pr --queued-stack --stack-prs <bottom-to-top-list>` with a fixed PR list across restarts. A stalled merge needs diagnosis before another branch mutation. Do not create a recurring automation to track this run.
8. **Stop at the ceiling.** Extending the run requires verification of the next patch and authorization within the user's scope.

**Reply:** each PR's verdict and evidence, what actually merged, the ceiling and the next unresolved gap.
